## 建议的 GitHub Release 文件

以下是最终发布的目标结构；预览包里的缺项标记不是已经完成的发行文件：

```text
qqmusic-convert-v1.1.0-windows-amd64.zip
  qqmusic-convert.exe
  LICENSE
  NOTICE.md
  THIRD_PARTY_NOTICES.txt
  使用说明.md
  README.en.md
  licenses/
  SOURCE_AVAILABILITY.md
  SHA256SUMS.txt

qqmusic-convert-v1.1.0-source.zip
  原创源码、公开算法夹具、构建脚本、文档、LICENSE、NOTICE 和第三方许可

qqmusic-convert-v1.1.0-corresponding-source.zip
  FFmpeg 对应源码、所有应提供的依赖源码、补丁、构建及安装脚本、版本清单和许可

SHA256SUMS.txt
RELEASE_MANIFEST.json
```

源码下载位置应与二进制的发行页放在一起，清楚说明版本和范围，且不要求额外付费。
GPLv3 第 6 节给出了多种二进制分发方式；若选择网络提供方式，需按该方式落实
对应源码访问。不要把三年书面提供承诺自动加入下载页；那是另一种方式，涉及实际履约。

## 本地预览材料

预览包会明确使用 `preview` 名称及 `NOT_READY_FOR_PUBLIC_BINARY_RELEASE` 标记。
每个包带哈希清单和发行状态，文件名不会把部分第三方源码标成完整对应源码。
源码与发行说明不包含个人电脑目录、歌曲名称、账号信息或登录密钥。

`SOURCE_AVAILABILITY.md` 必须如实区分：原创应用源码已整理、FFmpeg 自身源码已取得、
外部依赖与完整构建链尚未齐备。预览包可以本地核对，不应把它改名为正式发行来绕过缺项。

## 公开发行前核对

- [ ] 对应源码范围与实际静态二进制一致。
- [ ] 外部依赖版本／提交、补丁及许可均落实，没有 `latest` 或猜测值。
- [ ] 构建、链接及安装资料足以支持按适用许可证使用对应源码。
- [ ] 源码位置实际可访问，发行页上的指引与版本匹配。
- [ ] 发行清单与实际 EXE、组件和源码包的 SHA-256 一致。
- [ ] 已保留必要版权声明，项目 MIT 与第三方许可范围没有混淆。
- [ ] 真实音频、认证信息、私有路径和临时开发工具未进入公开包。

当前材料不声称二进制逐字节可复现，也不声称上述未完成项已经通过许可审查。
